# B6-offline plan — pipeline state machine, `warden resume`, examples/ replay in CI

## 1. Goal
`warden/pipeline.py` is the hand-written machine: hunt → plan → fix → verify → pr as five explicit steps, each fed
from `runs/<id>/artifacts/` and writing one artifact there. Implementations are injected (`Steps`): `warden run
--demo` runs demo.py's fixtures through the same machine the live steps will use, `warden resume <id>` continues
from the last completed artifact in the same log dir, and `examples/demo-issue-201/` is a recorded run CI replays
offline modulo run_id/timestamps. Base = main 77ae6f9; no existing signature changes; `run_demo` kept
(test_cost_cap_exits_4 monkeypatches it) and now delegates to the machine.

## 2. Rulings taken (none block; say so if you disagree)
- Brief signature kept, plus `stop_after: Phase | None = None` on `run_pipeline` (= `--dry-run`; demo.py no longer
  branches on dry_run). Alternative (each step checks ctx.dry_run) spreads one rule over five callables.
- Hidden `--run-id` on `warden run` (typer `hidden=True`) so the example records straight into
  `examples/demo-issue-201` with a matching run_id in result.json/index.html (vs. record + `mv` → foreign run_id).
- Live steps raise `NotReadyError` (has `.fix`); cli maps it to the DX block, exit 3 — pipeline.py never imports
  ui/typer (same pattern as `PrOpenError`).
- `cost_usd` (result, evidence Cost row) = `round(sum(ev.usd), 6)` over events.jsonl — the only number that survives
  resume and is right live (CostMeter puts usd on llm events). Demo steps put their fixture cost on one note per
  phase (`usd=`), so demo cost.jsonl is non-empty and the console timeline shows $.
- Machine calls `log.result(**result)` itself and returns the dict; cli only prints `evidence` when not `--json`.

## 3. State rule — artifact presence is the single source of truth
`MARKER = {hunt: issue.json, plan: plan.json, fix: candidate.json, verify: verdict.json, pr: pr.json}` under
`artifacts/`; a phase is complete iff its marker exists; writes are atomic (`<name>.tmp` → `os.replace`).
`completed_phases(run_dir) -> list[Phase]` = longest prefix of PHASES whose markers exist (a gap ends it). Why: the
marker IS the next phase's input, so "complete" and "consumable" coincide; a state.json or phase_done event could
disagree with the file that matters, and a half-run phase (orphan checkpoints, no marker) must rerun anyway. The
machine still emits a console-only note per phase (`{"text": "<phase> done → artifacts/<marker>", "phase_done":
phase}`), never read back. `runs/<id>/run.json` (top level) is the immutable manifest `{"mode": "demo"|"live",
"issue": int|null}`, written once on a fresh start; resume reads it to pick Steps.

## 4. Signatures (exact) — warden/pipeline.py
- `PHASES: tuple[Phase, ...] = ("hunt","plan","fix","verify","pr")`; `MARKER: dict[Phase, str]` as above;
  `Mode = Literal["demo","live"]`.
- `class Progress(Protocol)`: `phase(phase: Phase, text: str)`, `step(text: str)`, `cost(usd: float)`,
  `finish(text: str)` — `ui.PhaseLog` satisfies it; `class NullProgress` (moved from demo.py's `_NoProgress`).
- `@dataclass(frozen=True) class IssueRef`: `issue: int`, `title: str` (→ issue.json via asdict).
- `@dataclass(frozen=True) class PrOutcome`: `body: str`, `title: str`, `label: str | None`, `url: str | None`
  (body → pr_body.md; the rest → pr.json, written LAST so pr.json is the marker).
- `class NotReadyError(RuntimeError)`: `__init__(message, *, fix: str)`; attribute `fix`.
- `@dataclass(frozen=True) class StepContext`: `settings: Settings`, `log: EventLog`, `run_dir: Path`,
  `artifacts: Path`, `progress: Progress`, `yes: bool`, `json_out: bool`, `requested_issue: int | None`;
  `spent_usd() -> float` (re-reads events.jsonl; the log flushes per emit, so in-process events count).
- `@dataclass(frozen=True) class Steps`: `mode: Mode`, `hunt: Callable[[StepContext], IssueRef]`,
  `plan: Callable[[StepContext, IssueRef], Plan]`, `fix: Callable[[StepContext, Plan], Candidate]`,
  `verify: Callable[[StepContext, Plan, Candidate], Verdict]`, `pr: Callable[[StepContext, IssueRef, Plan,
  Candidate, Verdict], PrOutcome]`. Steps own their `progress.phase/step/cost` lines (headlines are step knowledge,
  e.g. citation count); the machine owns `progress.finish`, phase_done notes, all artifact I/O, run.json, result.json.
- `completed_phases(run_dir: Path) -> list[Phase]`; `load_inputs(artifacts: Path, upto: Phase) -> dict[Phase, Any]`
  (`model_validate_json`; raises `ValueError("cannot resume after X: artifacts/Y.json missing")`).
- `run_pipeline(settings: Settings, log: EventLog, steps: Steps, *, start_after: Phase | None, json_out: bool,
  yes: bool, progress: Progress | None, stop_after: Phase | None = None, requested_issue: int | None = None)
  -> dict[str, Any]`.
- `live_steps() -> Steps` (mode "live"; every step raises `NotReadyError("live pipeline lands in Phase B (see
  docs/warden-plan.md §5)", fix="use --demo for now")`).
Result dict (stable key set for `| jq`): `issue`, `verdict` (decision or null), `cost_usd`, `evidence` (pr_body.md
text; else plan JSON indent=2 when stopped after plan; else ""), `pr_url`, `resumed_from` (Phase or null).

## 5. Machine flow (`run_pipeline`)
1. `done = completed_phases(log.dir)`. Fresh (`start_after is None`): write run.json. Resume: run.json must exist
   with mode == `steps.mode` and `start_after == done[-1]` (else ValueError); `inputs = load_inputs(...)`;
   `progress.cost(spent_before)` (Fix line opens at the real running total); note in the next phase `{"text":
   "resumed after <phase>", "resumed_from": phase}`; `progress.step("resumed after plan; skipping hunt, plan")`.
2. For each phase after `start_after`: call the step with earlier outputs; atomic-write its marker (pr: body first,
   pr.json last); phase_done note; `break` when `phase == stop_after`. No try/except anywhere in pipeline.py.
3. Build result; `progress.finish(f"{decision} · body in {settings.runs_dir}/{run_id}/artifacts/pr_body.md")`
   (today's Total line, byte-identical with default runs_dir) or `"plan printed (--dry-run)"`; `log.result(**result)`.

## 6. Resume flow — cli.py
`resume(run_id, *, --json, --yes, --plain)`, lazy imports as in `run`. Missing events.jsonl → existing `fail("no run
<id> under …", fix="ls …")` (exit 1, pinned). Missing run.json → fail "run <id> predates resume", fix "re-run: warden
run --demo", 1. `"pr" in completed_phases` → fail "run <id> already complete", fix "warden console --run <id>", 2.
Else `EventLog(s.runs_dir, run_id, json_stream=…)` (append), `_err(f"run_id {run_id}   (resuming after {phase})")`,
steps = `warden.demo.demo_steps()` / `live_steps()` by mode, `run_pipeline(..., start_after=done[-1] or None)`.
`run`: creds/`--issue` checks unchanged (exit 2 before the machine); `--demo` → `warden.demo.run_demo(s, log,
dry_run=, progress=, yes=, json_out=)`; live → `run_pipeline(s, log, live_steps(), stop_after=…, requested_issue=)`.
A shared `_guarded()` holds the sanctioned catches: CostCap→4, PrOpenError→1, NotReadyError→3 (`fix=e.fix`).
`console` unchanged (a resumed run is one dir, one index.html); `warden.pipeline` imported only inside commands.

## 7. Demo Steps (demo.py) — same events/bytes as today, plus usd + phase_done notes
- `class DemoBackend(FakeBackend)`: `use(ref)` returns the image already created for `ref`; an unknown `img-NNNN`
  ref creates an image WITH that uuid and advances the counter past NNNN — so base=img-0001, candidate=img-0003,
  theater=img-0004 both in-process and after a resume in a fresh process. Constants `DEMO_TEST`, `DEMO_IMPL`.
- `demo_steps(*, crash_after: Phase | None = None) -> Steps` (mode "demo"; one DemoBackend in the closure). The
  step after `crash_after` raises `RuntimeError("simulated crash after <phase>")` before touching anything.
  hunt: three notes (last carries `usd=0.12`) + progress lines as today → `IssueRef(201, DEMO_TITLE)`.
  plan: Plan fixture; `progress.phase("plan", "reading issue #201, 1 citation")`; plan note (`usd=0.31`) → Plan.
  fix: `Box.from_ref(backend, s.base_image, log, phase="fix")`, two `copy_in`, seed test_results, note (`usd=0.80`)
  → `Candidate(issue, image_uuid, tool_turns=7, tests_added=[DEMO_TEST path], cost_usd=0.80)`.
  verify: `Box.from_ref` for base image AND `candidate.image_uuid` (phase="verify"; same ids in-process and on
  resume), re-seed test_results, `theater_check(base, DEMO_TEST)`, suite run, notes (`usd=0.15`) → Verdict fixture.
  pr: phase line, note `{"text","label"}` with `usd=0.04`, `progress.cost(0.04)`, THEN `evidence_table(...,
  cost_usd=ctx.spent_usd()` (=1.42), `calls_by_model={s.*_model: 2/11/37})` → `PrOutcome(body, title, label, None)`;
  pr_body.md byte-identical; no PR is opened (no `confirm_pr`).
- `run_demo(s, log, *, dry_run=False, progress=None, yes=False, json_out=False) -> dict` = thin wrapper over
  `run_pipeline(..., demo_steps(), start_after=None, stop_after="plan" if dry_run else None)`.
- Existing tests that change: NONE. Invariants relied on: stderr `run_id ` line, phase prefixes, `$1.42  PASS`,
  `reading issue #201, 1 citation`, result `verdict == "PASS"`, ≥1 sandbox event, `warden.demo.run_demo` name, cli
  import set (test_render builds its own events, never imports demo.py).

artifacts/{issue.json, plan.json, candidate.json, verdict.json, pr_body.md, pr.json}}`. Recording (in README, run

Normalisation (`tests/test_replay.py::normalise(run_dir) -> dict[str, Any]`): events.jsonl → dicts minus `ts`, `ms`
→ 0 when not null; cost.jsonl minus `ts`; result.json minus `run_id`; run.json and every `artifacts/*` verbatim (image
uuids are deterministic — a change is a real tree regression); index.html not compared (durations), only rendered.

## 9. Tests

in order, run.json, result keys, one finish, 5 phase_done notes, `completed_phases == PHASES`); `test_stop_after_plan`
