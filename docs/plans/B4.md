# B4 plan — verify/gate.py on FakeBackend

## 1. Goal
`run_gate` runs the deterministic quality gate on a candidate Box (full suite, mypy, ruff check + format,
alembic upgrade on an empty DB + single head, openapi drift), never mutates the candidate (every command is a
disposable fork), and returns the five Verdict fields plus per-command evidence rows. Offline-testable on
FakeBackend; C3 (migration round-trip) slots in as one more step later.

## 2. Public surface (all in warden/verify/gate.py)
- `GateCommands` — frozen dataclass of the shell strings + env the gate runs (module constant
  `DEFAULT_COMMANDS`). Fields: `suite="pytest -q"`, `mypy="mypy ."`, `ruff_check="ruff check ."`,
  `ruff_format="ruff format --check ."`, `db_create="createdb warden_gate"`,
  `alembic_upgrade="alembic upgrade head"`, `alembic_env={"DATABASE_URL": "postgresql://localhost/warden_gate"}`,
  `alembic_heads="alembic heads"`, `openapi_snapshot="make openapi-snapshot"`,
  `openapi_diff="git diff --exit-code --quiet -- openapi.json"`. Fabric's real targets/paths are unknown
  (risk 6) — overriding is a constructor kwarg, never a code edit.
- `GateStep` — frozen dataclass: `name`, `shell`, `exit_code`, `ms`, `tail` (last 2000 chars stdout+stderr),
  `ok` property. One per command; this is what the evidence table / console will render per row.
- `GateResult` — frozen dataclass whose fields map 1:1 to Verdict: `suite: dict[str,int]`, `mypy_ok`,
  `ruff_ok`, `alembic_single_head`, `openapi_drift`; plus `steps: tuple[GateStep, ...]`,
  `migration_roundtrip: bool | None = None` (C3 fills it; None = not run), properties `suite_ok`
  (suite step exit 0) and `ok` (suite_ok and mypy_ok and ruff_ok and alembic_single_head and not drift),
  and `verdict_fields() -> dict[str, Any]` (exactly the five Verdict keys, so C1 does
  `Verdict(decision=..., theater_failed_on_base=..., **gate.verdict_fields())`).
  Dataclass, not schemas.py: schemas.py holds LLM outputs requested via `LLM.structured()`; the gate is
  deterministic sandbox evidence, mirrors `TheaterResult` in theater.py, and schemas.py is forbidden here.
- `run_gate(candidate: Box, log: EventLog, *, commands: GateCommands = DEFAULT_COMMANDS, cwd: str = "/app",
  timeout: int = 900) -> GateResult`. Never raises on a red command (exit codes are evidence); raises only on
  backend errors. Runs ALL steps (no short-circuit) so every evidence row is filled. Emits one
  `log.emit("verify", "note", {"gate": verdict_fields + step exit codes}, ms=total)` at the end — the
  per-command sandbox RunEvents come free from `Box.run`.

Command order and parsing (each a separate `Box.run`, `keep=False` unless noted):
1. `suite` (timeout=timeout) → `suite` dict from the pytest summary line via
   `re.findall(r"(\d+) (passed|failed|errors?|skipped|xfailed|xpassed)", stdout)`, normalising `error`→
   `errors`; keys `passed` and `failed` always present (default 0) when at least one match; `{}` when
   nothing matched (collection crash / timeout) — verifier then lists "suite" under `not_verified`.
2. `mypy` → `mypy_ok = exit == 0`.
3. `ruff_check`, 4. `ruff_format` → `ruff_ok = both exit == 0`.
5. `db_create` with `keep=True` → child `db`; 6. `alembic_upgrade` on `db` with `env=alembic_env`;
   7. `alembic_heads` on `db` → `heads = count of non-blank stdout lines`;
   `alembic_single_head = upgrade exit == 0 and heads == 1` (one Verdict field carries both facts; the
   individual exits stay in `steps`). C3 later inserts `downgrade -1` + `upgrade head` on `db` after step 7.
8. `openapi_snapshot` with `keep=True` → child `snap`; 9. `openapi_diff` on `snap` →
   `openapi_drift = snapshot exit != 0 or diff exit != 0` (per brief: exit code of `git diff --exit-code`).
Steps 1–4 and 8 run on `candidate` directly (each run forks; candidate image is never modified).

## 3. FakeBackend vocabulary (warden/sandbox/fake.py)
- New `FakeImage` knobs, copied on fork like `test_results`: `gate_results: dict[str, int]` (command key →
  exit code; key is `" ".join(parts[:2])` if present in the dict else `parts[0]`), `suite_counts:
  dict[str, int]` (pytest summary counts), `alembic_heads: list[str]` (default `["abc123 (head)"]`).
- `pytest`: exit code unchanged (max of `test_results` per target) OR 1 if `suite_counts` has
  `failed`/`errors` > 0; stdout becomes a real summary line `"===== 2 failed, 5 passed in 0.10s ====="`
  (from `suite_counts`, else `1 passed` / `1 failed` derived from the exit code). Theater tests and demo.py
  only read `.ok`, so nothing breaks.
- `mypy` → `gate_results["mypy"]` (0: "Success: no issues found", else "Found N errors").
- `ruff check` / `ruff format` → `gate_results["ruff check"]` / `["ruff format"]`.
- `createdb`, `dropdb` → `gate_results[...]` default 0. `alembic upgrade` → `gate_results["alembic upgrade"]`;
  `alembic heads` → prints `alembic_heads` one per line, exit 0. `alembic downgrade` → default 0 (C3).
- `make` → `gate_results["make openapi-snapshot"]`; `git diff` → `gate_results["git diff"]` (1 = drift);
  `git status` → "" exit 0. Everything else keeps returning 127 unknown.
Seeding examples: `img.gate_results["mypy"]=1`, `img.alembic_heads=["a (head)","b (head)"]`,
`img.suite_counts={"passed":5,"failed":2}`. Existing tests in tests/test_box_and_theater.py stay untouched.

## 4. Tests (tests/test_gate.py, FakeBackend + EventLog(tmp_path))
1. `test_all_green`: fresh image → suite `{"passed":1,"failed":0}`, all four booleans green, `ok` True,
   `verdict_fields()` keys == the five Verdict names and `Verdict(decision="PASS",
   theater_failed_on_base=True, **fields)` validates.
2. `test_suite_failure`: `suite_counts={"passed":5,"failed":2}` → suite parsed, `suite_ok` False, `ok` False,
   other booleans still green.
3. `test_mypy_flips`: `gate_results["mypy"]=1` → `mypy_ok` False only.
4. `test_ruff_flips` (parametrised over `"ruff check"`, `"ruff format"`) → `ruff_ok` False only.
5. `test_alembic_flips` (parametrised: upgrade exit 1; two heads) → `alembic_single_head` False only.
6. `test_openapi_drift_flips` (parametrised: make exit 2; git diff exit 1) → `openapi_drift` True only.
7. `test_every_gate_command_emits_sandbox_event`: `EventLog.read` → sandbox events' `shell` equals the nine
   `DEFAULT_COMMANDS` shells in order, each with a matching `exit_code`; final event is the gate `note`.
8. `test_candidate_untouched_and_steps_recorded`: `len(steps)==9`, names unique, candidate uuid's fake
   image files unchanged after the run; `commands=` override is honoured (custom suite string appears).

## 5. Done-when
`uv run ruff check . && uv run ruff format --check . && uv run mypy warden && uv run pytest -q` green
(11 existing + ~10 new), then `git commit -m "feat(B4): verify gate on FakeBackend"`.

## 6. Risks
- Fabric's real `make openapi-snapshot` target, snapshot path, `DATABASE_URL` name and `createdb` flags are
  unknown; all live in `GateCommands` so A4/B6 can fix them from config without touching gate logic.
- `git diff` drift reads True if the implementer legitimately regenerated the snapshot but did not commit;
  fallback documented: hash-before/hash-after of the snapshot file in one shell.
- Suite timeout (900 s) vs Fabric suite length; timeout is a kwarg. mypy/ruff must exist in the base image.
- Fake vocabulary is shared with the fix/tools step — ruling in progress.md: B4 owns fake.py in wave 1.
- `alembic heads` output format drift (multi-line per head) would miscount; counting `(head)` markers
  first, non-blank lines second, guards it.

gate.py ~110 lines, fake.py +45 lines, tests/test_gate.py ~120 lines. No other files.
